# 0007 判定提示词拆机械层与氛围层，人格片固定在最前

- 状态：已采纳
- 日期：2026-11-07
- 影响范围：`config` 的 `internal` 提示词段、`speech/judge_persona.go`、`speech/prompt.go`、`speech/proactive.go`、`speech/dispatch.go`

## 背景

主动接话分两步：先判"要不要回"（判官），通过了才调生成。判官原来只有一段提示词，里面并排放着两类判断——"对象不是你 / 两人私聊 / 已经有人回答 / 刷屏接龙"这种与角色无关的硬条件，和"值不值得接、会不会冷场"这种全看性格的软判断。同一段里还写死了「与机器人职责相关：查新闻、锐评、解释规则、回顾群历史」，那是某一个人格的职责清单，却对所有群生效。

于是两个方向都错：内敛的人格（教师、客服）被按"能锐评就上"的尺度判定，该沉默时乱接话；外放的人格（雌小鬼）本该在玩梗时接一句，读到却先是"默认不插话"，人格形同虚设。

生成链路里人格的位置同样别扭：它被拼在 system prompt 倒数第二段，紧跟其后是按轮决定的【回复焦点】；而且四处调用点各自 `+= RenderPersona(...)`，挪一次顺序要改四处，漏一处那条链路的人格就落到末尾。

## 决策

判官 system prompt 拆成五段，顺序固定：

| # | 段 | 内容 | 谁说了算 |
| --- | --- | --- | --- |
| 1 | 人格片 | 只有 identity / personality / relationship | 群配置 |
| 2 | `_role` | 判官外壳：只判要不要回，不写回复 | 写死 |
| 3 | `_mechanical` | 对象、安全、时序、能力——命中就不回 | 写死，角色不得推翻 |
| 4 | `_vibe` | 该不该凑热闹、值不值得接 | 人格定尺度 |
| 5 | `_output` | JSON 契约（reply / long_form / focus / reason） | 写死 |

规则：

1. 机械层是硬约束，氛围层是软判断；给了人格只影响第 4 段。
2. 人格片只取三样。`system_prompt`（是给生成步骤的输出要求）、`sharedRules`（会与机械层打架）、`emotion`（对二值判断没有稳定影响）都不进。
3. 人格片放最前。生成链路同步：`ComposeSystemPrompt` 把人格块拼在第一段，【回复焦点】永远是最后一句；三处调用点（关键字 / 直答 / 主动接话）的拼装收口到 `ComposeSystemPrompt` + `groupPersonaBlock`。
4. system prompt 内部不允许出现按轮变化的内容。一旦插入，它之后的所有段都不再命中前缀缓存。

## 后果

- 每个群各有一条稳定前缀：人格片按群变化，之后四段逐字节相同，人格不换就一直命中。放弃的是跨群共享（人格放最后能让所有群共用前四段），换来的是指令层级——先立角色，再讲怎么干活。
- 判官多了几百 token，命中价约为未命中价的 1/30，可忽略。
- 「禁止自行编造答案」从第 1 句退到人格块之后，人格级要求可能与它冲突。这是刻意接受的；真出了问题的补救是把这一句单独提到人格块前面，而不是整体回退。
- 判官的身份从"中立第三方"变成"这个角色要不要开口"，排查"为什么没回"时要先分清是机械层拦的，还是氛围层觉得不值得。
- 判定与生成两处的人格口径分开维护：判官只认三样，生成认全套，改人格字段时要先问"这属于哪一层"。

## 被否的方案

- **判官不带人格**：那就必须内置一份通用尺度，而那份尺度实际来自某个人格（原文的"查新闻、锐评"），等于把一个角色的偏好伪装成平台默认值。
- **整块人格塞进判官**：`system_prompt` 会让判官以为自己要写回复，`sharedRules` 与机械层互相拆台；判定只需要"在不在乎"，不需要"怎么说"。
- **只在判官里加一行"你扮演 X"**：模型知道了名字，但仍按同一套标准判断，雌小鬼和教师的 yes 比例不会分开。
- **给人格加一个"话痨度"数值旋钮**：能调出"更爱说话"，调不出"教师只答求助、不接玩梗"这种有方向的差异。
- **人格继续留在 system 末尾**：缓存上没有损失（整段 system 本就逐字节稳定），但读起来是"规则说完了，顺便提一句你是谁"，人格成了补丁而不是前提。
- **把人格放进 user 消息**：每轮重发，还要跟聊天记录绑在一起，缓存与语义双输。
